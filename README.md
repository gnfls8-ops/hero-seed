# 히어로의 씨앗 (프로토타입)

초능력(염동력)을 가진 아이 **하람**의 보호자가 되어 여섯 달 동안 일정과 가르침으로 아이의 능력과 신념을 키우는 한국어 웹 게임 프로토타입입니다.
핵심 검증 질문은 “내가 가르친 가치관 때문에 아이가 이렇게 행동했구나”라는 인과관계가 느껴지는가입니다.

- 한 회차 6턴(턴당 한 달), 목표 10~15분
- 도트 방(육성) + 짧은 구조 미니게임(2·4·6턴) + 몇 년 뒤 성인 장면과 엔딩 3종
- 설치·로그인 없이 정적 파일로 실행, PC(키보드·마우스)와 모바일(터치) 공용

## 실행

```bash
npm ci            # 의존성 설치 (lockfile 고정 버전)
npm run dev       # 개발 서버 (http://localhost:5173)
npm run build     # 타입 검사 + 정적 빌드 → dist/
npm run preview   # dist 미리보기
npm run test      # 규칙 단위 테스트 (Vitest)
npm run test:e2e  # 빌드 후 브라우저 통합 테스트 (Playwright, Chromium)
```

- 브라우저 테스트를 처음 돌리는 환경에서는 `npx playwright install --with-deps chromium`이 필요합니다.
- 브라우저 테스트는 `dist`를 `/sub/path/` 하위 경로로 서비스해 GitHub Pages 저장소 경로와 같은 조건에서 검증합니다.
- `?dev=1`을 붙이면 개발용 패널(왼쪽 아래 DEV 버튼)이 열립니다.

## 조작법

| 환경 | 육성 화면 | 미니게임 |
| - | - | - |
| PC | 마우스 클릭, 또는 Tab으로 이동 후 Enter. 라디오 버튼은 화살표 | 방향키·WASD 이동, Space·E 행동, Esc 일시정지 |
| 모바일 | 탭 | 화면 방향 패드 4개 + 행동 버튼 |

- 미니게임은 행동 횟수 기반입니다. 이동 1칸 = 행동력 1, 벽 쪽으로 누르면 방향만 바뀌고 무료입니다.
- 행동 버튼은 바라보는 칸의 잔해를 치우거나(힘 40 미만 3, 이상 2) 대상을 구조합니다(1). 대상이 없으면 비용이 없습니다.
- 키를 누르고 있어도 운영체제 키 반복은 무시하며, 터치는 1탭 1행동입니다.
- 설정에서 효과음 끄기, 연출 속도(보통·빠르게·즉시), 터치 조작 버튼 표시(자동·항상·숨기기)를 바꿀 수 있습니다.

## 한 회차 흐름

타이틀 → 새 게임/이어하기 → 도입 → (월간 상태 → 일정 3칸 → 활동 결과 → [2·4·6턴 구조 미니게임] → 사건과 가르침 → 아이의 반응 → 월말 요약) × 6 → 몇 년 뒤 → 최종 사건 → 엔딩

모든 전환에는 명시적인 다음 버튼이 있고 대사는 자동으로 넘어가지 않습니다. 연출 중 다음 버튼을 누르면 먼저 전체 문장을 보여 줍니다.

## 디렉터리

```
src/core   상태·턴 진행(game.ts), 능력 변화(rules.ts), 성향·엔딩 판정(ending.ts),
           조건식(conditions.ts), 구조 미니게임 규칙과 경로 비용 계산기(rescue.ts),
           저장·검증(save.ts), 데이터 스키마 검증(schema.ts), 시뮬레이터(sim.ts)
src/data   수치(balance.ts), 활동(activities.ts), 사건(events.ts), 맵(maps.ts),
           엔딩(endings.ts), 한국어 문구(strings.ts)
src/game   Phaser 장면(scenes.ts), 캔버스 배치·배율(pixel.ts), 픽셀 스프라이트(sprites.ts)
src/ui     화면 전환(app.ts), 단계별 패널(views/), 저장소(store.ts), 모달, 효과음, 타자 연출
tests/unit 규칙 단위 테스트          tests/e2e  브라우저 통합 테스트
public/assets  아이콘(SVG)
```

- `src/core`는 Phaser와 DOM에 의존하지 않는 순수 함수입니다. UI(DOM)와 Phaser 장면은 `Store` 하나를 함께 구독합니다.
- 이벤트 조건은 `{ type, ... }` 객체와 허용된 비교 연산자(`>= > <= < == !=`)만 사용하며 문자열 eval은 없습니다.
- 앱 시작 시 `validateData()`가 사건 ID 중복, 누락된 후속 사건, 미래 사건 참조, 선택지 3유형 구성, 신뢰 변화 범위, 맵 크기·외곽 벽·대상 좌표, 최저 능력 구조 가능 여부를 검사하고 오류가 있으면 화면에 표시합니다.

## 데이터 조정

- 수치: `src/data/balance.ts` (초기값, 활동 효과, 가르침 효과, 미니게임 비용·보너스, 엔딩 기준값)
- 사건: `src/data/events.ts`
  - 필드: `id, turn, prerequisites, textVariants, choices(effects=teaching+trust, memoryTags), callbacks, minigameIntro`
  - `seen`은 데이터가 아니라 상태의 `eventHistory`로 관리합니다(같은 ID 중복 실행 차단).
  - 문단은 문자열 또는 `{ variants: [{ when: 조건[], text }] }`. 마지막 변형은 조건 없는 기본값이어야 합니다.
  - `{firstmem}`·`{firstturn}`·`{lastmem}`은 아이가 기억한 말로 치환됩니다(텍스트로만 표시).
- 맵: `src/data/maps.ts` (9×9 문자 격자, 좌표는 왼쪽 위 (0,0))
- 수정 후 `npm test`가 맵 최소 비용 표를 다시 계산해 확인합니다. 비용 조건이 깨지면 테스트가 실패합니다.

### 맵 좌표와 최소 비용 (테스트에 기록, `tests/unit/maps.test.ts`)

| 맵 | 시작 | 대상 좌표 | 최소 비용 (잔해 3 / 잔해 2) |
| - | - | - | - |
| 2턴 연습장 | (1,1) | 곰 인형 (4,4) | 13 / 12 |
| 4턴 구조 훈련 | (4,7) | 빨간 표식 (1,1), 우는 소리 (1,3) | 우는 소리 7, 빨간 표식 12, 둘 다 20(우는 소리 먼저)·22(규칙 순서) / 둘 다 18 |
| 6턴 시장 골목 | (1,7) | 상인 (1,3), 학생 (7,3), 증거 (4,1) | 상인 9, 학생 13, 증거 15, 시민 둘 19, 상인+증거 21, **전부 30** / **전부 26** |

- 최저 능력(힘 20, 제어 20 → 잔해 3, 행동력 24)으로 모든 맵에서 최소 1명 구조 가능.
- 6턴: 기본 예산으로는 전부 불가(30 > 24). 힘만 40 이상(26 > 24)이나 제어만 40 이상(30 > 28)으로도 불가. **힘·제어 모두 40 이상(26 ≤ 28)이면 전부 가능.** 기본 예산으로도 “시민 둘” 또는 “시민 하나 + 증거” 중 고를 수 있습니다.

## 규칙 요약

- 능력: 힘·제어 초기 20, 보호자 신뢰 초기 50 (0~100). 성향: 공감·원칙·불신·지배욕 각 초기 20 (0~100, 서로 독립).
- 활동: 학교(제어 +2), 초능력 훈련(힘 +4, 제어 +2), 봉사(힘 +1, 제어 +1), 가족 시간(신뢰 +4). 같은 활동은 한 달 최대 2회. 활동은 성향을 바꾸지 않습니다.
- 가르침(선택지 내부 유형): 책임과 보호(공감 +8, 원칙 +6), 제도 밖의 보호(공감 +5, 불신 +8), 힘에 의한 통제(지배욕 +8, 불신 +3). 각 선택지에는 별도 신뢰 변화(-2~+3)와 기억 태그가 있습니다. 화면에는 유형 이름을 표시하지 않습니다.
- 미니게임 보상: 구조 대상당 제어 +2(최대 +4). 증거는 기록·대사에만 반영. 미니게임 결과는 성향을 직접 바꾸지 않습니다.
- 엔딩 판정(순서 그대로): ① 지배욕 ≥ 60 그리고 지배욕 > 공감 → 빌런 ② 불신 ≥ 55 그리고 불신 > 원칙 → 다크히어로 ③ 그 외 화이트히어로.
- 최종 장면에서 “다른 방법도 생각해보자” + 신뢰 65 이상이면 아이가 말을 받아들이고 행동이 완화됩니다(엔딩 유형은 그대로).
- 판정은 프로토타입용이며 성향의 우열이나 현실의 도덕성을 뜻하지 않습니다.

## 저장

- 단계 전환·선택 확정·미니게임 유효 행동마다 `localStorage`에 작은 단일 스냅샷을 자동 저장합니다. 이전 정상 저장 1개를 백업으로 유지합니다.
- 중요 효과마다 적용 ID(`t3:activities`, `t4:minigame`, `t2:event:…`, `t5:advance`, `finale:choice`)를 기록해 이어하기·더블 탭·새로고침으로 보상이나 턴이 중복 적용되지 않습니다. 버튼은 “화면이 본 단계”를 함께 보내므로 연타해도 한 단계만 진행합니다.
- 저장이 손상되면 안내 후 백업 복원 또는 새 게임을 고릅니다. `localStorage`가 막히거나 용량 오류가 나면 메모리로 계속 진행하며 “자동 저장이 불가능합니다”를 표시합니다.
- 기기 간 이동: 상단 **저장 → 저장 파일 내보내기**(JSON) 후 다른 기기에서 **저장 파일 가져오기**. 가져오기는 1MB 이하, 형식·버전·수치 범위·열거값·사건/선택지 ID 일관성을 검사하고, 통과하면 교체 확인을 받은 뒤 반영합니다. 실패하면 현재 진행을 건드리지 않습니다. 가져온 문자열은 HTML로 해석하지 않으며, 기억 문장 등은 저장 파일이 아니라 게임 데이터에서 다시 만듭니다.
- 계정·자동 동기화는 없습니다.

## 배포 (GitHub Pages)

`vite.config.ts`의 기본 `base`는 상대 경로(`./`)라서 저장소 하위 경로(`https://<사용자>.github.io/<저장소>/`)에서도 이미지·JS가 그대로 로드됩니다. 절대 경로가 필요하면 `BASE_PATH=/저장소/ npm run build`.

1. 이 폴더를 GitHub 저장소로 올립니다(기본 브랜치 `main`).
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
3. `main`에 푸시하면 `.github/workflows/deploy.yml`이 단위 테스트 → 빌드 → Pages 배포를 수행합니다. 완료 후 Actions 실행 화면의 `deploy` 단계에 주소가 표시됩니다.

`dist`는 런타임 CDN 의존이 없는 정적 파일이므로 다른 정적 호스팅(Netlify, Cloudflare Pages 등)에도 그대로 올릴 수 있습니다.

## 구현 중 정한 세부 사항

- 등장인물: 아이 하람(성별을 정하지 않은 이름), 친구 민재, 교사 윤 선생님(학교 구조 훈련도 담당), 악역 블랙아웃. 보호자는 2인칭 “당신”으로 서술하고 호칭은 쓰지 않습니다.
- 4턴 구조 훈련의 “규칙과 구조 우선순위 충돌”: 규칙상 빨간 표식 인형이 먼저지만 우는 소리 인형이 더 가깝습니다. 우는 소리 인형을 먼저 구하면 막혀 있던 짧은 길이 열려 비용이 줄어듭니다(20 vs 22). 어떤 순서였는지가 사건 문장에 반영됩니다.
- 6턴 사건의 “가장 대표적인 과거 가르침”: 1~5턴에서 가장 많이 고른 유형(동률이면 최근), 그 유형의 **첫** 기억을 인용합니다.
- 엔딩의 “대표 가르침 2개”: 엔딩과 같은 유형의 처음·마지막 선택. 부족하면 최근 선택으로 채웁니다.
- 활동 문구는 활동당 9개(중립 6 + 가르침 성향별 3). 가장 많이 쌓인 가르침에 따라 성향 문구가 섞여 나오며, 한 회차 안에서는 반복을 피합니다. 선택은 회차 ID 기반으로 결정적이라 새로고침해도 같습니다.
- 성향은 숫자 대신 설명 문장(최대 3개)으로 표시하고, 방 소품(구급 포스터·순찰 지도·트로피)과 대기 대사가 가장 많이 쌓인 가르침에 따라 바뀝니다. 창밖 하늘은 턴이 지날수록 저녁으로 물듭니다.
- 미니게임은 행동력을 다 쓰거나 목표를 모두 처리하면 입력이 멈추고 “결과 보기”를 안내합니다(자동 전환 없음). 남은 행동력이 있을 때 결과 보기를 누르면 한 번 더 확인합니다.
- 픽셀 배율: 2배 이상 들어가면 정수 배율, 그보다 작으면 비정수 배율을 허용합니다. 미니게임 맵은 216×216(24px 타일 9칸), 방은 192×128.
- 효과음은 Web Audio로 합성하며 첫 사용자 조작 이후에만 켜집니다. 탭이 백그라운드로 가면 렌더링·효과음·입력을 멈춥니다.

브라우저 테스트 범위:
- PC 키보드만으로 새 게임 → 엔딩 완주(Tab·Enter·화살표로 메뉴, 방향키·WASD·Space·E로 미니게임), 키 반복 무시, Esc 일시정지 중 입력 차단
- 모바일 터치 에뮬레이션(Pixel 7 프로필)으로 일정·대화·미니게임 3회·엔딩 완주, 1탭 1행동, 버튼 가장자리 탭, 버튼 사이 빈 곳 탭 무반응
- 대화 중·미니게임 중·결과 화면 새로고침 후 복원, 보상 중복 없음, 다음 버튼·선택지 더블클릭
- 360×640, 390×844, 844×390, 768×1024, 1366×768: 가로 스크롤 없음, 주요 버튼이 화면 안에 있고 가려지지 않음, 글자 16/14px 이상, 터치 대상 44px·방향 패드 48px 이상, 미니게임 화면 세로 스크롤 없음, 맵 정사각형 유지
- 세로 → 가로 → 세로 회전 중 미니게임 상태 유지
- 저장 내보내기 → 새 브라우저 컨텍스트에서 가져오기, 잘못된 파일 거절, 손상 저장 백업 복원, localStorage 차단 시 경고·메모리 진행, 새 회차 덮어쓰기 확인
- `/sub/path/` 하위 경로 배포에서 JS·CSS·아이콘 로드
- 개발용 패널(dev=1 전용), 테스트 경로로 다크히어로 엔딩 도달

### 성능 측정

| 환경 | 방 화면 | 미니게임 |
| - | - | - |
| 헤드리스 Chromium, 1366×768, SwiftShader(소프트웨어 WebGL) | 60fps | 60fps |
| 같은 환경 + CPU 4배 감속 + 390×844 모바일 에뮬레이션 | 60fps | 60fps |

측정 방법: 각 화면에서 3초간 `requestAnimationFrame` 호출 수를 셌습니다. 실제 휴대폰·PC GPU에서 잰 값이 아니므로 “보통 모바일 기기 30fps 이상” 목표는 **실기기에서 아직 검증하지 않았습니다.**

### 검증하지 못한 항목

- **실제 기기**: iOS Safari, Android Chrome 실기기 테스트는 하지 않았습니다. 위 모바일 결과는 모두 Chromium 에뮬레이션입니다.
- **WebKit**: 작업 환경에 WebKit 브라우저가 없어 자동 검증하지 못했습니다(`npx playwright install webkit` 후 프로젝트 추가 가능).
- **실기기 성능**: 위 측정은 헤드리스 소프트웨어 렌더링 기준입니다.
- **효과음**: 재생 코드는 동작하지만 헤드리스 환경이라 실제 소리는 귀로 확인하지 못했습니다.
